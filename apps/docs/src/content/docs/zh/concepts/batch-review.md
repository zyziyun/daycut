批量是千剪（Reelfold）一次做很多条视频的方式，审片是你不用一条条看完也能放心的方式。每个文件都会自动做质量检查，你只看例外：没通过检查的、从通过的里随机抽出的一小部分，以及等你点头的剪辑。

![Mac 应用的收件箱：只列出需要你处理的片子和决定，每条都写了原因](../../../../assets/shots/home-I1-inbox.png)

## 为什么重要

96 个文件从头看到尾，一天就没了，而大部分其实没问题。千剪把你的注意力花在真正需要的地方，审片时间跟问题数量挂钩，而不是跟文件数量挂钩。

## 怎么运作

```
计划 → 预估 → 试点 → 全量 → 审片（只看例外）→ 打包
```

1. **计划。** 每条短视频是一个任务：长录像里的一段，或者文件夹里的一条素材。长录像由 AI 先起草选段清单（标题、hook、按词边界对齐的区间），你过一遍再开剪。
2. **预估。** 跑之前先告诉你机器时间、占用空间和 API 费用。超出预算会拒绝运行。
3. **试点。** 先完整跑几条就停下。你在真实成片上检查版式、字幕、hook 和响度，调好设置再确认。
4. **全量。** 任务在你的 Mac 上并行跑，最费时的部分共享（每个素材只转写一次）。可以续跑：崩了或者退出了，再开一次就行，做完的步骤不会重做。失败或标红的太多、或者花费超出预算时，熔断器会自动暂停。
5. **审片。** 只看例外。
6. **打包。** 通过的视频按平台分文件夹放好，带封面、发布文案和排期表。整个包有一个由清单哈希生成的确认码，改动任何内容都会换一个新码。不会上传任何东西。

### 自动检查

| 检查 | 查什么 |
|---|---|
| 响度和真峰值 | 偏离平台目标超过 1 LU，或者峰值过高 |
| 丢词 | 每个剪辑都重新转写一遍，不小心剪掉的词会标红 |
| 字幕幻觉 | 语音识别凭空编出来的字幕行 |
| 时长 | 超出平台上下限（红），或不在最佳区间（提醒，附建议：加速、删减、去掉冷开场） |
| 标题长度 | 超过平台字数，或平台要求标题却没有 |
| 安全区 | 字幕跑出平台安全框 |
| 音画同步 | 声音和画面对不上 |
| 黑帧、卡帧 | 意外的黑屏或画面卡住 |
| 隐私 | 录屏课程：裁切碰到了你排除的区域，比如参会者头像那一列 |
| 屏幕检查 | 录屏课程：弹窗、菜单没关，字太小看不清（提醒） |

### 「被标记」是什么意思

没有任何红色检查失败的任务是**绿灯**，有一项失败就是**红灯**。提醒会显示在卡片上，但不会变红。默认还会从绿灯里随机抽 10% 给人看，因为绿灯只是必要条件，不是充分条件。试点的任务也会被标记。

### 通过和修改

审片页上可以通过，或者写明原因退回。没被抽中的绿灯可以一键全部通过。退回的任务会回到重新规划。小改动不用重剪：改一句字幕、换个 hook、掐头去尾、剪掉一段、换封面或改文案，都只重跑受影响的步骤。如果改字幕时加了或少了实际说出的字，会被拒绝，除非音频里确实说的是新文字。

所有任务里待确认的去口癖剪辑会汇总到一张表上。你确认之前，只剪自动判定的部分。

## 在 Mac App 里

在首页直接说批量的需求，比如「把这节课切成 20 条竖屏，发抖音和小红书」。项目会先跑试点，需要你时出现在收件箱里。审片时你看到的就是被标记的那几条。

## 用 Claude Code 技能

一样直接说，比如「这 80 段口播都初剪一下，我只看有问题的」。技能底层用的是 `python -m vstudio.batch`（`plan-segments`、`plan`、`estimate`、`run --pilot`、`review`、`run --confirm-pilot`、`package` 或 `deliver`）。
