项目是千剪（Reelfold）里的一份工作：用一个配方处理一组条目。剪一条口播，是只有 1 个条目的项目；把一节课切成 50 条竖屏切片，是有 50 个条目的项目。结构一样，工具一样，跟数量无关。

## 为什么重要

一条和一百条是同一种东西，所以活变多了也不用换工具。项目里的每个条目并行处理，共享最费时的部分（每个素材只转写一次、只建一份术语表），中途崩了能接着跑，也会在同样的地方停下来问你。流程学一次就够。

## 怎么运作

从上到下是这样一条链：

```
工作区（你的 persona 或某个客户）→ 系列 → 项目（一个配方）→ 条目 → 成片（每个平台一份）
```

- **条目**来自你交给它的东西：一个素材文件夹（每个文件一个条目）、一份选题清单、CSV 的每一行、N 集，或者从一条长录像里规划出的选段。
- **参数**从通用到具体逐层覆盖：配方默认值 → 系列 → 项目 → 条目 → 你在检查点给出的回答。
- **检查点**是该由你拍板的地方：接受哪些去口癖的剪辑、用哪个开场 hook、保留哪些选段、选哪张封面、这条能不能发。跑到检查点时，这个条目会停在「需要你」的状态。这不算失败，其他条目照常跑。
- **成片**放在 `exports/<条目>/<平台>-<方向>`，每个文件旁边有封面和发布文案，另有一份记录每个文件校验值的清单。

### 项目文件夹

| 路径 | 里面是什么 |
|---|---|
| `project.yaml` | 可以直接改的「真相」：配方、参数、输入、条目、你的回答 |
| `items/<条目>/` | 每个条目的工作区：手写的文件，以及工作流自己的 `work/` 和 `out/` |
| `state/` | 运行状态（批量数据库、缓存、检查点内容）。不要手动改 |
| `exports/` | 成片、封面、发布文案、`manifest.json` |
| `AGENTS.md`、`CLAUDE.md` | 一页简要说明，在这个文件夹里打开 Claude Code 或 Codex，它就知道该看哪份流程、能用哪些命令 |

### 工作文件夹和 `.vstudio/`

不是每份活都从配方项目开始。技能在一个普通文件夹里剪片（里面有 `final/` 成片、`REPORT.md`、`post.md`）时，也会把它登记下来，唯一写入的是一个 `.vstudio/` 子文件夹：`status.json` 记录实时状态（进行中、等你、已完成、失败，当前步骤、进度、心跳），`work.json` 记录这是一个被收录的工作文件夹。如果一个「进行中」的记录长时间没有心跳，会显示为已中断。

### 收件箱和系列

- **收件箱**汇总所有项目里待你决定的检查点。同类问题会归到一起，比如二十个条目里同一类口癖剪辑，可以一次确认。预算和授权类的问题永远不会被默认回答。
- **系列**是给固定栏目准备的预设：配方、参数、发布节奏、哪些检查点自动用默认值。系列里新建的项目会全部继承。

## 在 Mac App 里

首页把你的一句话变成一个或多个项目。「全部项目」列出它们和实时状态，「收件箱」显示需要你的事，点开项目能看到每个条目和成片。

## 用 Claude Code 技能

技能会登记每一份活，Mac App 不用导入就能看到。开始时，有合适的配方就运行 `python -m vstudio.project new`，没有就运行 `python -m vstudio.project touch <文件夹> --status running --stage plan`；长步骤中更新步骤和进度，要问你问题时标记 `--status waiting --needs-you`，结束时标记 `--status done`。以前做的旧文件夹可以用 `python -m vstudio.project adopt <文件夹>` 补登记。
