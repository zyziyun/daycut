你会得到从一条长录像里切出来的一组竖屏切片。每条有自己的标题、开场 hook、字幕、封面和发布文案，每个平台单独导出一份。

![屏幕共享讲座切片联系表：顶部标题带写着系列名和章节，下面是共享屏幕，穿插章节卡和记笔记面板](../../../../assets/shots/longform-slices.jpg)

## 开始之前

- **一条长录像**：直播回放、网络研讨会、演讲、播客或屏幕共享课，常见长度 30 到 120 分钟。
- **大概想切几条**，每条多长。
- **一份术语表**，字幕才能写对。
- **如果是会议录屏**，先看一帧画面。参会者小窗、名字标签要框成隐私区域，保证不会出现在任何一条切片里。

## 在 Mac 应用里

1. 在首页输入框里说清楚，把录像拖进来，比如「这场直播切 12 条，发小红书和抖音」。
2. **方案**里写明用哪个流程、切几条、每条多长、发哪些平台。千剪（Reelfold）只转写一遍录像，然后起草一份选段表：每行有标题、章节、hook、几条要点，以及为什么值得切。
3. **审核选段**。这一步最好别跳过：删掉不要的、调整起止、改标题。起止点总会落在词与词之间。会议录屏还要在画面上框出隐私区域。
4. **批量**在你的 Mac 上跑，所有切片并行：去口癖、字幕、排版、封面、文案、每个平台一份导出，每个文件都会自动质检。
5. 只**审核**被标出来的：需要你确认的口癖、亮红灯的质检、抽查的几条绿灯。改字幕、修起止、换 hook、改封面字和标题这类小改动，不用重新剪。
6. 在发布周历里逐个平台发布，最后由你按下发布。

## 用 Claude Code 技能

告诉 Claude 这是什么录像、想切几条。只出一门课或几集时，技能走 `workflows/longform-to-short`；一次切很多条时走 `workflows/batch`。选段草稿来自：

```bash
python3 -m vstudio.batch plan-segments --source raw/livestream.mp4 --count 12 --min 45 --max 150 --provider auto
```

它会写出 `segments.draft.yaml`。渲染之前先和 Claude 一起过一遍。之后 Claude 会规划批量任务，告诉你预计的机器时间、占用空间和 API 费用，先试跑几条给你看，确认后再跑剩下的。

`--provider` 决定由谁起草选段：你配置好的模型、任一支持的服务商，或者 `none`（离线的规则选段）。发给服务商的只有逐字稿文本。规则选段比较粗，每一行都要看。

## 两种版式

| 版式 | 适合 | 效果 |
|---|---|---|
| 分栏 | 屏幕共享讲课、研讨会、写代码 | 上面是标题带（系列名 + 章节）或主讲人摄像头，下面是共享屏幕，裁切会跟着内容走，放大到字看得清。每条带章节卡和记笔记面板。 |
| 整画面重构 | 一个画面拍下来的口播或播客 | 整个画面转成竖屏：跟人脸、居中裁切，或放在模糊背景上。 |

屏幕共享如果按人脸重构，字根本看不清，所以有幻灯片或代码的录像请选分栏。分栏的细节见[课程切片](/docs/zh/guides/course-slicing/)。

## 值得知道的选项

| 选项 | 默认（应用） | 作用 |
|---|---|---|
| 选段条数 | 12 | 草稿里提几条。 |
| 最短 / 最长 | 45 秒 / 160 秒 | 每条切片的长度范围。 |
| 选段规划 | auto | 用哪个模型起草选段，或用规则。 |
| 语速 | 1.2× | 正文加速，保持音调。 |
| 去气口力度 | standard | `gentle` / `standard` / `tight` / 关闭。 |
| 系列名 | 空 | 显示在标题带和封面上。 |
| 隐私遮挡区域 | 无 | 每一帧都会涂掉的矩形（参会者小窗、名字标签）。 |
| 发布平台 | 小红书 3:4、抖音 | 任意竖屏平台，字幕按各自界面摆放。 |

## 示例指令

- 「这场两小时的直播切 15 条，每条 45 到 90 秒，发抖音和视频号。先给我看选段表。」
- 「这是 Zoom 研讨会，右边是参会者小窗，别露出来。切 10 条竖屏，带章节卡。」
- 「最好的五条各做三个 hook 版本，我想测一下。」
- 「第 4 条开头太早了，去掉第一句，标题也换一下。」
